# ADR 0004. Клиент API для iOS генерируется из описания OpenAPI (спайк S6)

**Статус:** принято по итогам спайка S6 (23.09.2026): **годится**, план Б (клиент вручную) не нужен.
**Связано:** PLAN.md, §7.2 («OpenAPI-генератор, если пройдёт S6»), таблица спайков §10; код — `ios/Packages/GorodkiAPI`,
`backend/src/Gorodki.Api/Infrastructure/OpenApi`, `contracts/openapi.v1.json`, `contracts/samples`.

## Контекст

У сервера уже 13 адресов и 40 схем, и их будет больше. Писать клиент на Swift руками — значит вручную поддерживать
каждое поле и каждый код ошибки; расхождения вылезут только на телефоне. Критерий спайка из плана:
**«пыточный» набор DTO проходит**.

## Решение

- Сервер отдаёт описание API (ASP.NET Core 10, OpenAPI 3.1). Тест сервера фиксирует его в `contracts/openapi.v1.json`
  и держит копию в пакете `GorodkiAPI`: изменил адреса и не обновил контракт — сборка сервера падает.
- Пакет `ios/Packages/GorodkiAPI` генерирует клиент плагином
  [swift-openapi-generator](https://github.com/apple/swift-openapi-generator) при сборке; сгенерированный код в репозиторий
  не попадает. Типы — `Components.Schemas.*`, методы — `Client.startRun(…)`, `claimLoop(…)`, `getTerritory(…)`…
- «Пыточный набор» — `contracts/samples`: ответы, записанные **самим сервером** его настройками JSON (тест `ApiSamplesTests`).
  Swift-тесты разбирают каждый и гоняют клиент на подставном транспорте (метод, путь, параметры, тело, коды ответов).

## Что нашёл спайк и как исправлено

| Находка | Чем грозила | Исправление |
|---|---|---|
| Все числа описаны как «целое **или строка**» (веб-настройки JSON разрешают читать числа из строк) | Каждое число в Swift — неудобный тип-вариант | Сервер принимает числа только числами (`JsonNumberHandling.Strict`) — заодно строже проверка ввода |
| Перечисления без `type: string` | Генератор мог не понять тип | Преобразователь документа ставит `type: string` |
| Не отмечены обязательные поля у части схем (конфиг, диапазоны номеров) | Лишние опционалы в Swift | Поле без `null` в типе — обязательное: сервер пишет все поля всегда |
| **Необязательная ссылка на объект (`oneOf: [null, $ref]`) — генератор молча выбрасывает поле** | `vehicleShare`, `carLaunch` правил лиги просто пропали бы в приложении | Такая ссылка превращается в обычную без пометки «обязательное» (`null` → `nil`); скрипт сверил: все 40 схем дошли до Swift полностью |
| У ошибок нет поля `code` и дополнительных полей | Приложение не отличило бы `run_not_found` от `chunk_conflict` и не увидело бы `problems`, `overlaps` | У `ProblemDetails` — поле `code` и «любые дополнительные поля» |
| У адресов нет `operationId` | Нет методов клиента | Каждому адресу — имя (`WithName`) |
| Даты .NET — с долями секунды (`.1234567+00:00`), стандартный декодер генератора их не читает | Время от времени падал бы разбор ответа | Всё время в API — миллисекунды (`activeFromMs` в конфиге); даты остались только в служебном `/health`, клиенту задан декодер с долями секунды |
| Двоичные поля (`byte[]`) описаны как `format: byte` — генератор делает из них обычную строку | Биты тумана пришлось бы раскодировать вручную | В OpenAPI 3.1 нужен `contentEncoding: base64` — теперь это `Base64EncodedData` (найдено при добавлении тумана) |
| `type` у ошибки — ключевое слово Swift | — | Генератор сам переименовал в `_type` (сверено, не потеря) |

## Последствия

- Формат ответов меняется только вместе с контрактом: тест сервера сравнивает живое описание с `contracts/openapi.v1.json`,
  тест образцов — сериализацию с `contracts/samples`; Swift-тесты — что клиент всё это понимает. CI: `backend` и `ios-core`.
- UUID в клиенте — строки (так генератор понимает `format: uuid`); при необходимости оборачиваем в `UUID` на стороне приложения.
- Пакет подключён к приложению вместе с сетевым слоем (`project.yml`, [ios-app.md](../architecture/ios-app.md)).
  Сборка плагина в Xcode из командной строки требует `-skipPackagePluginValidation` — флаг стоит во всех `xcodebuild`
  в `ios.yml` и `ipa.yml`.

## Как проверили

- Генерация и сборка пакета на Linux (WSL, Swift 6.4): ~67 с с нуля, ~6 200 строк кода клиента, предупреждения — только о
  неиспользованных `import` в сгенерированном коде.
- 9 Swift-тестов: 6 на разбор 13 образцов (null, диапазоны, словарь площадей, вложенные массивы координат, «призрак»,
  полный конфиг, ошибки с `problems` и `overlaps`), 3 на клиент целиком (заявка петли → 202, кусок → 409 с кодом и занятыми
  номерами, карта с параметрами запроса).
- Сверка «каждое поле описания есть в Swift-типе» по всем 40 схемам — без потерь (после исправления `oneOf`).
