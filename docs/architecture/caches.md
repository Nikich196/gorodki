## Тайники

- **Набор** — таблица `caches`: название значка, редкость, подсказка, широта и долгота, версия набора мест
  (`set_version`, сейчас 1), пометка `proposal` (как Арена и кварталы в наборе OSM) и объект OSM (`osm_ref`). Начальные
  20 мест — `CacheSeed` (данные миграции): обычных 10, редких 6, эпических 3, легендарный 1 (вместо 20/12/6/2 из PLAN — по
  уменьшенному плану). На карте тайников нет.
- **Находка** — «пройти в 30 м в валидном забеге» (`CacheRules.Finds`, чистая функция): путь тот же, что открывает туман
  и засчитывает визиты (`JudgedPath`) — точки с плохой точностью пропускаются, разрыв по правилам отрезков рвёт путь, 30 с
  перед разрывом не считаются; из машины тайник не найти. Отрезок между соседними точками тоже считается (редкие точки
  велосипеда). Время находки — первая точка пути в 30 м (по часам сервера). Лига любая.
- **Когда** — стадия «тайники» фонового обработчика (`CacheProcessor`, по образцу тумана): один раз за забег, когда он
  завершён и все точки на месте (или сутки после закрытия сервером); отметка `runs.caches_processed_at` — в той же
  транзакции, что и находки; ошибка — пауза `caches_retry_at` (1, 2, 4… минуты). Находка одна на (тайник, игрок) —
  уникальный индекс: свой найденный тайник второй забег не находит. Повтор записанного забега (демо) тайников не находит.
- **`GET /collection`** — все тайники набора, сначала легендарные: ненайденный — силуэт (только редкость и подсказка),
  найденный — название, `foundAtMs`, `finderNumber`, `goldFrame`. **Координат в ответе нет никогда** (тест
  `CollectionTests` это проверяет). Контракт не менялся.

### «№ N нашедших» и золотая рамка — приватность

Находка говорит «игрок был у тайника тогда-то». Поэтому чужая находка (раздел 4 [egor-server.md](../guides/egor-server.md))
учитывается в номере только с `cache_finds.visible_at` — границы публичности момента записи
(`TerritoryReader.VisibleAtAsync`: ≈20–25 минут, у демо-аккаунта сразу). Своя находка видна себе сразу. Номер —
`1 +` число чужих находок, **уже видимых**, раньше своей по порядку `(visible_at, found_at, id)`; `goldFrame` — номер 1.
Иначе игрок, стоящий у тайника, по скачку номера узнал бы, что здесь только что был другой.

Следствие: номер может вырасти только в первые ≤25 минут после записи своей находки (чужая, записанная чуть раньше, ещё
скрыта), дальше не меняется. В ответе нет ни времени, ни ника, ни номера чужих находок — только порядок.

Точка — последняя принятая точка активного забега (не присланная телефоном: иначе скрипт триангулирует тайник из любых точек), лимит запросов, только пока фишка активна |

| **Админка тайников** | Пока правка — миграцией |

## Рюкзак

- **«Припасы»** (`Backpack.GrantAsync`) — в транзакции визитов (`VisitProcessor`, под блокировкой игрока), когда путь
  забега посчитан: одна фишка за каждые полные 2 км засчитанного пути **этого забега**, не больше 4 за игровые сутки (по
  началу забега) и 12 занятых ячеек. Повтор записанного забега фишек не даёт. Выдаются только «Радар» и «Заморозка
  серии», по очереди (первая — «Радар»). Числа — `SupplyRules`.
- **Ячейку занимает** фишка, пока она не истекла (7 дней до активации) и не израсходована: «Радар» — пока остались метры,
  «Заморозка серии» — пока её не потратила серия.
- **`POST /me/inventory/{id}/activate`** — своя фишка (чужая — `404 item_not_found`); идёт забег (`runs.status = active`) —
  `409 run_active`; уже активирована — `409 item_active`; истекла — `409 item_expired`. Активация — одной командой с
  условием. Брошенный телефоном забег держит активацию, пока его не закроет сервер (`RunRetention`).
- **«Радар»** — в открытии тумана (`FogProcessor`, `FogStamp.WithRadar`): «Радары», активированные до начала забега,
  открывают первые метры засчитанного пути радиусом ×`radarMultiplier` (25 → 50 м); израсходованное списывается в той же
  транзакции, `remainingMeters` уменьшается (3 000 м на фишку). Телефон рисует свой туман без «Радара» — сервер точнее.
- **«Заморозка серии»** — моменты активации идут в серию (`StreakEndpoints.FreezesActivatedAtAsync` → `StreakRules`).
- **Не сделано:** «Магнит», «Компас», «Сундук» не выдаются; ставки в дуэлях; «ночью фишек нет» (§3.7) — «Припасы»
  выдаются за дистанцию после забега, а не на карте.

## Решено Claude — можно пересмотреть

| Решение | Почему |
|---|---|
| Номер нашедших — по моменту видимости находки другим, при равенстве — по времени находки | Номер окончателен через ≤25 минут и ничего не выдаёт; «по времени находки» мог бы меняться днями (забег из офлайна) |
| `visible_at` находки — граница публичности момента **записи** (после конца забега), а не прохода у тайника | Строже к приватности, тот же помощник, что у ленты |
| Удаление аккаунта стирает его находки — номера остальных сдвигаются вниз | Проще и полнее по закону; вариант — обезличивать строку, чтобы номера не менялись |
| Повтор записанного забега не находит тайники и не даёт «Припасов» | Демо-повтор иначе отнимал бы рамку у игроков |
| «2 км» считаются по каждому забегу отдельно, путь — без обрезки 200 м | Выдача — одно действие над одним забегом; километры не выдают места |
| «Радар» действует в забегах, начатых после активации; несколько «Радаров» тратятся по очереди | Активации во время забега нет; так понятно, какой забег «под Радаром» |
| Найденный значок остаётся в «Коллекции» навсегда | PLAN §3.14: «значки „Коллекции“ — вечные» |

## Риски

- **Репозиторий публичный:** координаты тайников видны в коде (`CacheSeed`) и в этом документе — сжульничать легко. Для
  показа приемлемо; закрыть — новый набор мест (`set_version`) из файла вне репозитория.
- Места проверены только по данным OSM, не на месте: данные OSM бывают неполными (школа или стройка без разметки).
- Номер нашедших и рамка в первые ≤25 минут предварительные (раздел про приватность) — приложению стоит не обещать рамку
  «навсегда» сразу после находки.
