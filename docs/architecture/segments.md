## Как засчитывается проход

Чистая функция `SegmentEffortDetector` (`Gorodki.Domain/Segments`), тесты — `SegmentEffortDetectorTests` без Docker.

- **Путь** — только засчитанный судьёй отрезков той версии правил, с которой начат забег (`RunJudgements`): куски без
  разрывов судьи (`JudgedPath`: точка разрыва и 30 с перед ней не в счёт), точки с плохой точностью пропускаются. Это и
  есть «все точки прошли правила лиги».
- **Ворота старта** — круг 25 м вокруг начала линии. Старт — место пути, ближайшее к началу линии, за **последний** заход в
  ворота (вернулся к старту — часы пошли заново).
- **Ворота финиша** — круг 25 м вокруг конца линии, **после** старта. Финиш — ближайшее к концу линии место за этот заход.
  Обратное направление не засчитывается: ворота финиша без старта перед ними ничего не значат.
- **Время интерполируется**: моменты старта и финиша — на прямой между соседними точками пути, до миллисекунды.
- **Коридор 30 м**: каждая точка между стартом и финишем не дальше 30 м от линии, иначе старт сброшен.
- **Вдоль всей линии**: места точек на линии идут без пропусков длиннее разрыва точек — срезать изгиб внутри коридора
  нельзя.
- **Разрыв точек**: соседние точки дальше 100 м (Бег) / 200 м (Вело) — где был игрок, неизвестно, проход рвётся.
- **«Бег» быстрее 30 км/ч** (длина линии / время) не засчитывается. У «Вело» предел дают правила лиги (судья).
- В одном забеге проходов может быть несколько — после финиша поиск идёт дальше.

## Где запускается

Стадия «отрезки» фонового обработчика `CaptureWorker` — `SegmentEffortProcessor`, как туман: один раз за забег, когда он
завершён и все точки на месте (или давно закрыт сервером). Повтор записанного забега (демо) проходов не даёт — как
дистанцию и пост.

- **Повтор не дублирует**: в той же транзакции ставится `runs.segments_processed_at`, второй проход видит отметку; уникальный
  индекс `(run_id, segment_id, started_at)` не даст записать проход дважды даже при ошибке в коде.
- **Ошибка** забега — пауза `CaptureWorker.RetryDelay` (`runs.segments_failures`, `segments_retry_at`), остальные забеги
  обрабатываются.
- **Блокировка**: `pg_advisory_xact_lock(8, лига)` — два забега одной лиги, посчитанные одновременно (второй экземпляр
  сервера во время деплоя), не свергают одного короля дважды ([jobs.md](jobs.md#пространства-блокировок)).

## Приватность

- **Граница публичности.** Проход другие видят с `segment_efforts.visible_at` — границы публичности **конца забега** по
  часам сервера (`TerritoryReader.PublicAt`: +20 минут, вверх до 5-минутной границы), как визиты и пост о забеге. Не по
  моменту прохода: иначе таблица показала бы «прошёл 20 минут назад» про игрока, который ещё бежит рядом. Демо-аккаунт —
  сразу, как его захваты.
- **Свои проходы — сразу**: `myBestTimeMs`, своя корона и своё место в таблице.
- **В ответах только длительность** (`timeMs`): ни момента прохода, ни забега, ни координат. Линия отрезка (`line`) —
  общая, не чей-то след.
- **Ники** — по правилу карточки игрока: свой — всегда, чужой — с согласия (`public_profile`), иначе «Игрок #1234»
  (`LeaderboardEndpoints.Pseudonym`). Игроки, удаляющие аккаунт, в таблицах уже не показываются (как в ленте).
- **«Местная легенда»** считает проходы за 30 игровых суток: окно сдвигается только в полночь по Минску, по уходу прохода
  из окна не узнать его время точнее даты.

## Адреса

| Адрес | Что отдаёт |
|---|---|
| `GET /segments?league=run\|bike` | Отрезки лиги (общие и только её) по алфавиту, у каждого — корона идущего сезона (между сезонами — `null`) |
| `GET /segments/{id}?league=` | Линия, корона сезона и за всё время, «Местная легенда» (30 суток, лиги вместе), своё лучшее время в лиге. Отрезка нет в этой лиге — 404 `segment_not_found` |
| `GET /segments/{id}/leaderboard?league=&season=` | Лучшее время каждого игрока, до 50 мест; одинаковое время — одно место (1, 2, 2, 4), выше тот, кто прошёл раньше; своё место — `mine`. Без `season` — за всё время |

Неверная лига или сезон меньше 0 — 400 `segments_invalid`. Корона — лучший видимый проход; при равном времени — первый.
Контракт (`contracts/openapi.v1.json`, образцы `segments`, `segment`, `segment-leaderboard`) не менялся.

## «Тебя свергли с трона» — точка подключения для «Входящих» (#139)

Таблица `app.segment_dethronements` — по строке на (проход, кого он сверг):

| Столбец | Что |
|---|---|
| `id` | Случайный номер (`Guid.NewGuid()`) — без времени внутри |
| `user_id` | Кого свергли |
| `segment_id`, `league` | Где: отрезок и лига (название — из `segments.name`) |
| `effort_id` | Проход нового короля (удалили его — например, с аккаунтом — событие уходит каскадом) |
| `season` | Номер сезона, корону которого отняли; `null` — сезонную не отнимали |
| `all_time` | Отняли корону за всё время |
| `visible_at` | С какого момента можно показать: не раньше, чем другие увидят сам проход (и не раньше записи) |

Пишет её `SegmentEffortProcessor` в транзакции прохода: новый проход быстрее лучшего прохода **другого** игрока на отрезке в
лиге — в сезоне прохода и/или за всё время (свой рекорд себя не свергает; равное время короны не отнимает). Если один игрок
потерял обе короны — одна строка с `season` и `all_time = true`.

Что сделать «Входящим»: читать **только свои строки с `visible_at ≤ now`** (индекс `(user_id, visible_at)`), вид события
`InboxKind.Dethroned` (приоритет — второй после нападения, §3.17), текст без рода, например «Тебя свергли с трона на
„Набережная Мухавца (восток)“». Без ника нового короля, без времени прохода. Либо переносить строки в свою таблицу событий
(тогда — с отметкой, что перенесено), либо читать её напрямую.

## Данные игрока

- **Удаление аккаунта**: проходы и события уходят каскадом (`user_id`, а проходы — и вместе с забегом), проверено
  `AccountDeletionTests` (у Анны есть проход и событие «свергли»).
- **«Мои данные»** (`/me/export`): проходов в выгрузке пока **нет** — в ответе `AccountExportResponse` нет поля под них, а
  контракт в этой задаче не меняется. Нужно добавить раздел «проходы отрезков» (отрезок, лига, сезон, время прохода,
  момент старта) — вместе с правкой описания API и его копии в приложении.

## Решено Claude 15.10 — можно пересмотреть

| Что | Как сейчас | Почему |
|---|---|---|
| Числа правил не в игровом конфиге | `SegmentRules` в коде: ворота 25, коридор 30, 30 км/ч, 30 суток, 200–800 м | Раздел конфига входит в описание API и копию в приложении (`ios/`), а их в этой задаче менять нельзя; приложению эти числа не нужны. Перенести — одной правкой контракта |
| Разрыв точек | 100 м (Бег) / 200 м (Вело) | Как у тумана (§7.2) |
| Старт и финиш | Ближайшее к концу линии место за заход в ворота | «Время интерполируется»; кто стоял у старта, теряет секунды ожидания |
| Отрезки по лигам | Набережная — только Бег (`bicycle=no`), велодорожка — только Вело, остальное — общее | Не звать на дорожку тех, кому туда нельзя |
| Видимость | С границы публичности конца забега | Как визиты и пост о забеге (заготовка #146) |
| «За всё время» | Включает и проходы до Сезона 0 (полевые тесты) | Рекорд — не земля; если нужно «с чистого листа», считать с Сезона 0 |
| Обрезка 200 м и приватные зоны | Не применяются к проходам | Проход говорит только «прошёл общий отрезок за N секунд», и то через 20 минут после конца забега |
| «Местная легенда» при равенстве | Тот, кто набрал число раньше | Детерминированно |
| Отрезок не в лиге запроса | 404 `segment_not_found` | В списке лиги его нет |
