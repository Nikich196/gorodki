# Задачи по расписанию (Hangfire)

Фоновая работа сервера — гибрид ([ADR 0005](../adr/0005-background-jobs.md), решение #54 «В»):

| Что | Чем | Почему |
|---|---|---|
| Захваты, визиты, туман, раскрытия, откаты | Свой обработчик `CaptureWorker` ([captures.md](captures.md#обработка)): раз в 5 с или по сигналу, строго один поток | Это очередь: итог нужен за секунды после заявки, движок участков однопоточный (ADR 0003) |
| «Раз в час», «в 00:00 по Минску» | **Hangfire** — `ScheduledJobs` | Надёжный планировщик: повтор упавшей задачи, время Минска, дашборд для показа (§11) |

Код: `backend/src/Gorodki.Api/Infrastructure/Jobs/ScheduledJobs.cs`. Пакеты — `Hangfire.AspNetCore` и
`Hangfire.PostgreSql` (версии — в `backend/Directory.Packages.props`).

## Расписание сейчас

| Задача (`id`) | Когда | Что делает | Код |
|---|---|---|---|
| `refresh-tokens-purge` | каждый час (`0 * * * *`), часовой пояс Минска | Стирает истёкшие refresh-токены ([auth.md](auth.md)) | `RefreshTokenRetention.PurgeExpiredAsync` |

Ещё в часовой чистке `CaptureWorker.HousekeepingAsync` (перенос в Hangfire — задача E6 Егора, по образцу выше): журнал
захватов старше 7 дней, забытые забеги, сырые точки старше 14 дней, удаление аккаунтов, суточный срез рейтингов.

## Как добавить задачу (образец для E6)

1. **Сервис** с методом `Task` (можно `Task<int>` — число попадёт в дашборд как результат), зарегистрированный в
   `Program.cs` (`AddScoped`). Время — только через `TimeProvider`/`GameClock`, как везде.
2. **Одна строка** в `ScheduledJobs.Register`:

   ```csharp
   jobs.AddOrUpdate<RunRetention>("raw-points-purge", r => r.PurgeRawPointsAsync(CancellationToken.None), Cron.Hourly(), minsk);
   ```

   `CancellationToken.None` — заглушка: Hangfire подставит свой токен (остановка сервера). Расписание — cron:
   `Cron.Hourly()` (`0 * * * *`), `Cron.Daily()` (`0 0 * * *` — полночь по Минску, раз часовой пояс `minsk`),
   `"5 * * * *"` — в 5 минут каждого часа. Имя задачи — латиницей через дефис; по нему Hangfire обновляет запись, а не
   плодит копии (перезапуск, второй экземпляр во время деплоя).
3. **Убрать** эту стадию из `CaptureWorker.HousekeepingAsync` и её название — из списка в
   `CaptureWorkerTests.Every_stage_of_the_pass_and_of_the_hourly_cleanup_is_tried_even_if_each_one_fails`.
4. **Тесты**: метод зовётся напрямую на настоящей базе (как `AuthFlowTests.Expired_refresh_tokens_are_erased_and_the_rest_stay`)
   и **второй раз подряд ничего лишнего не делает**; в `Gorodki.Api.Tests/Jobs/ScheduledJobsTests` — проверка, что задача
   стоит в расписании (имя, cron, Минск). Сам Hangfire в интеграционных тестах выключен — включать не нужно.

Правила:

- **Идемпотентность обязательна.** Hangfire повторяет упавшую задачу (до 10 раз с растущей паузой), а после сна Render Free
  пропущенные запуски догоняет одним. Два запуска подряд не должны ничего испортить.
- **Земля — не из Hangfire.** Задача, которая меняет участки, тайлы или журнал захватов, пойдёт параллельно
  однопоточному движку. Такое либо остаётся в `CaptureWorker`, либо берёт те же блокировки PostgreSQL, что и обработчик
  (номера — в ADR 0005), — сначала обсудить с Claude.
- **Одна задача — одна работа.** Ошибка одной не должна отменять другие: пять чисток — пять задач, а не одна.

## Выключатель

`Jobs:Hangfire` (на Render — переменная `Jobs__Hangfire`), по умолчанию включён. Без строки подключения к базе Hangfire не
подключается вовсе. Тестовые серверы его выключают — иначе он при старте пошёл бы в базу: `UnreachableDatabase`, тесты
контрактов, `ApiFactory`. Тест самого Hangfire включает его явно: `new ApiFactory(database, scheduledJobs: true)`.
Выключенный Hangfire значит, что токены никто не стирает, — это только для тестов и отладки.

## Дашборд `/admin/hangfire`

- **Только администратору**: роль проверяется по базе, как у админских адресов (`AdminEndpoints.AdminIdAsync`), — снятая
  роль действует сразу. Без входа — 401 (политика «по умолчанию — только с входом»), игроку — 403.
- **Только чтение**: кнопок «запустить», «удалить», «повторить» нет, а такие запросы в обход кнопок сервер не выполняет.
- Строка подключения к базе на страницах не показывается (`DisplayStorageConnectionString = false`).
- **Как открыть в браузере.** Браузер не шлёт заголовок `Authorization`, поэтому токен приходит в адресе один раз:
  `https://<адрес сервера>/admin/hangfire?access_token=<access-токен администратора>`. Сервер кладёт его в куку
  (`HttpOnly`, `Secure`, только для `/admin/hangfire`) и сразу перенаправляет на тот же адрес без токена — в истории
  браузера он не остаётся. Access-токен живёт 15 минут: потом страница ответит 401 — открыть заново со свежим токеном.
  Токен в адресе принимается только здесь и на хабе SignalR (`Program.cs`); журнал запросов ASP.NET пишется с уровня
  Warning, так что адрес с токеном сервер в лог не пишет.

## Бюджет: память, соединения, база

| Ресурс | Сколько | Как держим |
|---|---|---|
| Память | ≈ +6–11 МБ к ≈170 МБ процесса (грубый замер 25.09: локально, Release, один процессор, сервер без нагрузки) | Один исполнитель вместо 20 по умолчанию; Render Free — 512 МБ |
| Соединения | свой пул **3** (`ScheduledJobs.MaxPoolSize`) рядом с пулом приложения **8** (`AppDbContext.MaxPoolSize`) — PLAN §7.3 | Опросы Hangfire раз в 15 с не дают пулу закрыть соединения, поэтому **все 3 заняты постоянно** (замер: `gorodki-hangfire: 3`). Видны в `pg_stat_activity` под именем `gorodki-hangfire` и в числе `connections` у `/health/ready` для админа. Во время деплоя два экземпляра — вдвое больше, недолго |
| База | Схема `hangfire` — 12 таблиц, Hangfire создаёт их сам при первом старте (`PrepareSchemaIfNecessary`), миграция EF не нужна | Выполненные задачи Hangfire стирает сам через сутки: при часовой задаче это пара десятков строк |
| Нагрузка | Несколько коротких запросов в минуту: очередь раз в 15 с, отметка сервера раз в 30 с, планировщик. Открытый дашборд — статистика раз в 10 с | — |

Render Free засыпает после 15 минут без запросов — тогда задачи ждут пробуждения. Пингер (#39) держит сервер бодрствующим.

## Тесты

- `Gorodki.Api.Tests/Jobs/ScheduledJobsTests` (без базы): расписание — имя, cron, часовой пояс Минска; пул 3 и имя
  соединения; без выключателя Hangfire даже не регистрируется.
- `Gorodki.IntegrationTests/ScheduledJobsTests` (настоящая база): задача записана в схеме `hangfire`, выполняется самим
  Hangfire (запуск «по кнопке» из кода) и повтор ничего лишнего не стирает; дашборд — 401 без входа, 403 игроку, 200 админу,
  команды не выполняются; вход из браузера через `?access_token=` и куку. В остальных интеграционных тестах Hangfire
  выключен.
