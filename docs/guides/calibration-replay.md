# Разбор записанных забегов: калибровка R, `A_min`, `R_min`

> Инструмент к полевому тесту №1 ([протокол](field-test-1.md), раздел 1, «Разбор», и раздел 4). Готов 25.09.2026.

Разбор прогоняет записанные точки забега через **тот же код** игры, но с другими числами, и показывает, что было бы
при другом R, `A_min` и `R_min`. Второй выход на улицу для этого не нужен. Без разбора `A_min` и `R_min`
не откалибровать: у отклонённых заявок сервер не хранит ни контура, ни площади, а у незамкнувшихся попыток П4 заявок
нет вовсе ([протокол, раздел 4](field-test-1.md#4-что-записать-для-калибровки)).

Что с чем прогоняется:

| Шаг | Чей код | Какие числа можно менять |
|---|---|---|
| Судья отрезков (точность, скорость, датчики) | телефона — `SegmentJudge` (GameCore) | — (лига и порог новичка — как у забега) |
| Детектор петли: где телефон заявил бы петлю | телефона — `LoopDetector` (GameCore) | R (нижняя и верхняя граница, множитель), путь, порог оценки площади |
| Кольцо петли: разрыв внутри, путь, недоход до начала ≤ R | сервера — `TrackJudging`, `LoopRing` | те же числа детектора |
| Контур P (шаг A) и фильтры площади и ширины | сервера — `CaptureShapeBuilder` | `A_min`, `R_min` |

По умолчанию числа — из кода, они же версия 1 игрового конфига: R = clamp(1,62·√(accᵢ² + accₙ²), 20, 50) м, путь
≥ 150 м, оценка площади ≥ 1 000 м², `A_min` = 2 500 м², `R_min` = 9 м.

## 1. Что нужно

- **Компьютер с WSL (Ubuntu), Linux или Mac**, где есть Swift 6.2+ и .NET 10 — те же, что для тестов GameCore
  и сервера ([CONTRIBUTING.md](../../CONTRIBUTING.md)). На Windows без WSL Swift нет.
- **Файл «Мои данные»** игрока — JSON от сервера (`GET /me/export`,
  [auth.md](../architecture/auth.md#мои-данные)). В нём точки забега с точностью (без неё не посчитать R) и данные
  датчиков (без них судья не узнает транспорт и шаги), а ещё итоги заявок — для сверки.

Другие выгрузки не подходят: в GPX нет ни точности, ни датчиков, а пробный забег «Лаборатории» точек наружу
не отдаёт.

## 2. Как получить файл

**В приложении — «Отладка» → «Мои данные»** (сделано 25.09, #126): «Выгрузить «Мои данные»» → «Отправить файл» →
сохранить на компьютер (AirDrop, Telegram «Избранное», почта себе). Файл `gorodki-my-data.json` лежит и в «Файлы» →
«На iPhone» → «Городки» → `Exports`. Нужны вход и развёрнутый сервер. «Отладка» видна в пробной сборке (`ipa.yml`
с галочкой `probe`) и ролям demo/admin ([ios-app.md](../architecture/ios-app.md)).

Точки на сервере хранятся 14 дней ([runs.md](../architecture/runs.md#хранение)): у забегов 24.10 — до 07.11. Выгрузка
после этого придёт уже без точек, и разобрать её нельзя.

**Куда положить файл — только вне репозитория**: в нём настоящие маршруты, а репозиторий публичный. Например,
`C:\Users\nikic\gorodki-field\` — в WSL это `/mnt/c/Users/nikic/gorodki-field/`. На всякий случай `.gitignore` не даёт
добавить в git файлы `gorodki-my-data*.json`, `*.loops.json` и `*.report.html`.

## 3. Запуск — одна команда

В WSL, из корня репозитория:

```bash
bash backend/tools/Gorodki.Calibration/calibrate.sh /mnt/c/Users/nikic/gorodki-field/gorodki-my-data.json \
  --r-min 15,20,25 --min-area 1500,2500,3500 --min-half-width 6,9,12
```

Первый запуск собирает обе половины — несколько минут, дальше — секунды. Без параметров берутся текущие числа.
Числа — через запятую, дробь — через точку (`1.62`). Перебираются **все сочетания**: в примере 3 × 3 × 3 = 27 строк.

| Параметр | Что это | Сейчас |
|---|---|---|
| `--r-min` | Нижняя граница R, м | 20 |
| `--r-max` | Верхняя граница R, м (больше 50 не ставить — ниже почему) | 50 |
| `--r-factor` | Множитель в формуле R; `0` — R всегда равен `--r-min` («фиксированный R») | 1.62 |
| `--min-path` | Путь петли не короче, м | 150 |
| `--min-est-area` | Телефон не заявляет петлю с оценкой площади меньше, м² | 1000 |
| `--min-area` | `A_min`, м² | 2500 |
| `--min-half-width` | `R_min`, м | 9 |
| `--run <id>` | Только этот забег (иначе — все забеги файла) | — |
| `--newcomer` | Судья с порогом точности новичка (35 м вместо 25) — если забег шёл без засчитанных захватов | — |

Что получится:
- таблицы — на экране;
- рядом с входным файлом — `gorodki-my-data.loops.json` (петли, найденные детектором) и `gorodki-my-data.report.html`
  (те же таблицы и картинки). HTML открывается в любом браузере, в том числе на телефоне, внешних файлов не требует.

Попробовать без настоящего забега — на синтетическом (квадрат, узкая полоса, незамкнутая дуга):

```bash
swift run --package-path ios/Tools/LoopReplay LoopReplay --synthetic --out /tmp/synthetic.json
bash backend/tools/Gorodki.Calibration/calibrate.sh /tmp/synthetic.json --r-min 15,20,25 --min-area 1500,2500,3500
```

## 4. Как читать

**Заметки сверху.** По каждому забегу: сколько точек, сколько принял и отбросил судья, сколько разрывов следа.
«На сервере: …» — что сервер решил по заявкам этого забега на самом деле. **Сверка:** строка с текущими числами должна
дать столько же петель и те же исходы. Если нет — причины ниже, в «Чего разбор не знает».

**«Итог по сетке»** — строка на каждое сочетание чисел:
- «Петель» — сколько заявок отправил бы телефон;
- `applied` — контур прошёл шаг A (площадь и ширина в порядке);
- `too_small` — площадь меньше `A_min`; `too_narrow` — нигде нет «пятна» радиусом `R_min`;
- «Другие» — отказы до контура: `not_closed` (концы дальше R), `too_short`, `segment_broken:…` (след порван внутри петли),
  `empty` («туда-обратно» ничего не обвело).

**«Петли»** — каждая найденная петля каждого варианта детектора:

| Столбец | Что значит |
|---|---|
| Рис. | Номер картинки ниже (одна петля, найденная разными вариантами, — одна картинка) |
| Точки | Номера первой и последней точки петли |
| Замыкание | `crossing` — след пересёк сам себя; `proximity` — вернулся ближе R к прежней точке |
| R, м | R для концов этой петли по формуле детектора |
| Недоход, м | Расстояние между концами петли |
| Оценка телефона, м² | Грубая площадь, с которой телефон отправил бы заявку |
| Контур, м² | Площадь контура P на сервере — её сравнивать с `A_min` |
| Полуширина, м | Радиус самого большого круга, который помещается в контур, — его сравнивать с `R_min` (сервер проверяет чуть строже: сжатием контура с острыми углами, поэтому у самой границы решает исход, а не это число) |
| Исход | По сочетаниям `A_min`/`R_min`; одинаковые — одной группой |

**Картинки «след + контур».** Север сверху, метры — как в движке (UTM 34N), внизу слева — масштаб. Серое — весь забег,
синее — след петли, × — точка, которую отбросил судья, зелёная точка — начало, красная — конец, пунктир между ними —
замыкающая хорда, зелёный пунктирный круг — R вокруг начала, заливка — контур P, оранжевый пунктирный круг —
наибольший вписанный круг. Под картинкой — таблица исходов: строки — `A_min`, столбцы — `R_min`.

**Что смотреть по протоколу** ([раздел 3](field-test-1.md#3-порядок), таблица петель):
- П2 — ни одного `too_small` при выбранном `A_min`; П2о — насколько разбросана площадь у порога;
- П3у и П3ш — где `too_narrow`, где `applied` (и см. ниже про узкую полосу);
- П4а, П4б, П4в — при каком R замкнулась бы каждая попытка (столбец «Недоход» против «R»);
- П5 — петли нет или отказ;
- петли, которых никто не задумывал (стоянка, параллельные тротуары, куски разных попыток).

## 5. Что уже видно на синтетическом следе

Синтетика — не улица, но две вещи из неё стоит знать до теста:

- **Квадрат 60 × 60 м даёт не 3 600 м², а ≈ 3 300.** Детектор замыкает петлю сближением, как только вернулся ближе R
  к её началу, — примерно за 20 м до угла, и хорда срезает кусок. При `A_min` = 3 500 такой квадрат уже `too_small`.
- **Узкая полоса 12 × 300 м при нынешних числах даёт `too_small`, а не `too_narrow`.** Полоса уже R (20 м), поэтому
  на обратном пути детектор замыкает петлю сразу, как только оценка площади дойдёт до 1 000 м² (`--min-est-area`), —
  сервер получает кусок ≈ 1 000 м² и отказывает по площади раньше, чем по ширине. Вся полоса (≈ 3 600 м²) была бы
  `too_narrow`; при `--min-est-area 2500` так и выходит. Значит, П3у на тесте, скорее всего, покажет `too_small`,
  и проверка `R_min` по ней — через разбор с другим `--min-est-area`.

## 6. Чего разбор не знает

- **Не из следа:** разрешение «Движение» (без него сервер отклоняет все заявки — в заметках будет предупреждение),
  лимиты, «старше 3 часов», защита от мультиаккаунтов, что станет с землёй на карте. Маски OSM не вычитаются —
  их пока нет и на сервере.
- **Перезапуски приложения.** После перезапуска телефон начинает детектор заново, а в выгрузке этого не видно: петлю,
  начатую до перезапуска, разбор найдёт, а телефон её не заявлял.
- **Дыры в номерах точек.** Разбирается только начало следа без пропусков — как и на сервере; сколько точек осталось
  за дырой, написано в заметках.
- **R больше 50 м.** Детектор ищет соседей в ячейках по 50 м: при `--r-max` больше 50 часть замыканий он не увидит.
- **Новичок.** В выгрузке не сказано, судился ли забег с порогом новичка: такой забег разбирать с `--newcomer`.
- **Версия конфига.** Остальные числа (упрощение 2 м, шипы, отростки, пороги судьи) — из кода, то есть версии 1.

## Как устроено

Инструмент в двух половинах, потому что детектор петли есть только у телефона (Swift), а контур строит только сервер
(C#): «сервер петли сам не ищет» ([sync.md](../architecture/sync.md)). Обе половины зовут настоящий код, своих копий
правил в них нет.

- `ios/Tools/LoopReplay` — отдельный Swift-пакет, зависит от `ios/Packages/GameCore` по пути и не меняет его. Читает
  «Мои данные», судит точки (`SegmentJudge`, датчики — как их подаёт сервер) и прогоняет детектор (`LoopDetector`)
  с каждым набором чисел — так же, как `RunSession` на телефоне: отброшенная точка в след не идёт, на разрыве детектор
  начинается заново. Пишет JSON с точками и найденными петлями.
- `backend/tools/Gorodki.Calibration` — консольная программа на `Gorodki.Domain`, как `Gorodki.GeoBench`. Для каждой
  петли — `TrackJudging` → `LoopRing` → `CaptureShapeBuilder` с каждой парой `A_min` × `R_min`, как в
  `CaptureProcessor`; таблицы — Markdown, картинки — SVG в одном HTML. `calibrate.sh` запускает обе половины подряд.
- Тесты: `swift test --package-path ios/Tools/LoopReplay` (детектор на синтетике: квадрат с шумом ±5 м, полоса 12 м,
  дуга, разрыв следа, чтение выгрузки) и `backend/tests/Gorodki.Calibration.Tests` (исходы шага A на тех же фигурах,
  чтение выхода Swift, отчёт). Обе половины — в CI (`ios-core`, `backend`).
