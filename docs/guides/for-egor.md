- Реальное время на SignalR: подсказки «тайлы изменились» и «заявка решена» ([realtime.md](../architecture/realtime.md)).
- Рейтинг «Кто открыл больше» по ежедневному срезу ([fog.md](../architecture/fog.md)), визиты, приватные зоны,
  защита от мультиаккаунтов, удаление аккаунта и «Мои данные» (закон 99-З, [auth.md](../architecture/auth.md)).
- База: PostgreSQL + PostGIS через EF Core с миграциями ([data-model.md](../architecture/data-model.md)).
- Тесты: больше 200 быстрых (xUnit v3) и интеграционные на настоящей базе в Docker (образ Supabase) — их гоняет CI.

**iPhone-часть** (`ios/`, Swift):
- каркас приложения (сборки Free и Paid), экран «Проверка установки», раздел «Лаборатория» (прогулка, карта с туманом),
  Live Activity и виджет;
- пакеты `GameCore` (правила, античит, детектор петли, туман), `GorodkiAPI` (клиент сервера из OpenAPI,
  [ADR 0004](../adr/0004-openapi-swift.md)), `GorodkiSync` (офлайн-очередь забега и фоновая досылка,
  [sync.md](../architecture/sync.md)), `GorodkiNetwork` (токены, вход, реальное время), `GorodkiPersistence` (база на GRDB);
- собрать приложение можно только на Mac. Своего Mac пока нет, поэтому собирает CI (GitHub Actions на macOS),
  а на iPhone его ставят с Windows через Sideloadly ([install-on-iphone.md](install-on-iphone.md));
- экрана входа в приложении ещё нет: логика входа готова, экран ждёт Google Client ID (#4) и дизайн.

Подробности по дням — в [JOURNAL.md](../JOURNAL.md) (новое сверху).

## 4. Как сделать каждую

Здесь коротко, по шагам — в самих задачах. Где написано «примерно так», интерфейс сервиса мог поменяться: ищи по смыслу.

**1. 2FA на GitHub.** Аватар справа вверху → **Settings → Password and authentication** → включить двухфакторную проверку
через приложение-аутентификатор. Коды восстановления сохрани у себя — не в репозиторий и не в чат.

**2. Supabase** — облачный PostgreSQL. Бесплатно: 500 МБ, пауза после недели простоя (§9).
Создавать ничего не нужно: 23.09 Claude с твоего входа завёл в твоём аккаунте организацию и в ней проект `gorodki`
(Франкфурт, бесплатный план, Data API выключен), применил миграции и пригласил Никиту владельцем организации. Пароль базы
уже у Никиты. Тебе осталось:
1. Смени пароль **аккаунта** Supabase (вход на supabase.com): он передавался в переписке. Пароль **базы** не меняй: он
   у Никиты для строки подключения сервера на Render — после смены сервер не подключится к базе, а новый пароль
   пришлось бы снова передавать Никите.
2. Включи 2FA в настройках аккаунта.
3. Проект по умолчанию, который был в аккаунте до «Городков», нам не нужен: удали его или оставь себе. Проект `gorodki`
   и его организацию не удаляй и не переименовывай.
4. Напиши в задаче «сделал» — без паролей и кодов.

Ключи API Supabase (`anon`, `service_role`) нам не нужны — никому их не отправляй. Строку подключения тоже: она уже у Никиты
([deploy-render.md](deploy-render.md)).

**Как передать секрет** (§9: «канал — одноразовая ссылка»; понадобится для ключа Sentry, п. 5):
1. Открой любой сервис одноразовых записок — записка сгорает после первого прочтения.
2. Вставь только сам секрет, без подписи, от чего он.
3. Ссылку пришли Никите в личку, а что это за секрет — отдельным сообщением.
4. Никита открыл — ссылка сгорела. Если он видит «уже прочитано», а сам не открывал — секрет перехватили: перевыпусти его
   и повторите.

Никогда не пиши секреты в задачи и PR (репозиторий публичный — их видит весь интернет), в код, в общий чат, на скриншоты.

**3. Сервер и тесты у себя.** Всё по [getting-started-windows.md](getting-started-windows.md): .NET 10 SDK, Git, IDE
(Rider, Visual Studio или VS Code), `git clone`, затем из папки репозитория:

```powershell
cd backend
dotnet test --solution Gorodki.slnx
dotnet run --project src/Gorodki.Api
```

Команды `dotnet` — всегда из папки `backend`: там лежит `global.json` с версией SDK и запуском тестов через
Microsoft.Testing.Platform. Из корня репозитория `dotnet test` его не видит и падает с `MSB1001: Unknown switch --solution`.

Открой http://localhost:5080/scalar и вызови `GET /health`. Без Docker интеграционные тесты пропускаются, а без базы сервер
стартует без входа и профиля — так и задумано. Docker Desktop нужен, только если хочешь гонять интеграционные тесты у себя.
На Windows сервер до тебя не запускался: CI — на Linux, у Никиты — WSL. Если у тебя тест упал, а в CI он зелёный, — это наша
ошибка, а не твоя: пришли вывод целиком.

**4. Первый PR.**

```powershell
git switch main
git pull
git switch -c chore/codeowners-backend
```

В [.github/CODEOWNERS](../../.github/CODEOWNERS) удали строку-комментарий «Когда друг примет приглашение…» и добавь в конец:

```
/backend/   @Nikich196 @trinotox64
```

Никиту в строке оставляем: в CODEOWNERS побеждает последнее подходящее правило.

```powershell
git add .github/CODEOWNERS
git commit -m "chore(infra): Егор — ревьюер backend/ в CODEOWNERS"
git push -u origin chore/codeowners-backend
```

На странице репозитория нажми **Compare & pull request**, заполни шаблон, в разделе «Зачем» напиши `Closes #<номер задачи>`.
Дождись зелёных проверок. Сливает Никита. После этого GitHub будет сам звать тебя ревьюером на PR, где меняется `backend/`.
Одобрение для слияния не требуется: смотри, когда есть время, и спрашивай в комментариях всё непонятное. Лучшей подготовки к защите не найти.

**5. Sentry.** Зарегистрируйся на sentry.io. **Регион хранения данных — EU**: его выбирают при создании организации,
потом не поменять (§9). Включи 2FA. Создай проект для iOS-приложения: план подключает `sentry-cocoa` без персональных данных (§7.2).
Нужен ли отдельный проект для сервера — спроси Никиту. Ключ проекта (DSN) сохрани; куда его положить, скажет Claude, когда будет
подключать Sentry, а передать его — одноразовой ссылкой (см. «Как передать секрет» в п. 2 выше). Сайт не открывается
из Беларуси — напиши Никите: доступность сервисов из РБ план проверяет отдельно (§9).

**6. cron-job.org.** Render Free засыпает без запросов, Supabase Free встаёт на паузу после недели простоя. Поэтому в плане
пингер «с реальным запросом к БД» (§2, D7).
1. Сейчас: заведи аккаунт (и 2FA, если сервис её предлагает).
2. После того как Никита развернёт сервер ([как](deploy-render.md)): новое задание (примерно так: Cronjobs → Create) —
   `GET https://<адрес сервера>/health/ready` **каждые 10 минут** (Render Free засыпает после 15 минут без запросов).
   Этот адрес проверяет базу ([Program.cs](../../backend/src/Gorodki.Api/Program.cs)), а `/health` — нет. Адрес даст Никита,
   уведомления о сбоях отправляй себе на почту.
3. Проверь: в истории задания ответы 200. Запасной вариант по плану — UptimeRobot.
4. Ответ 503 — это сбой, и письмо придёт не зря: в теле ответа видно, что случилось — база недоступна (`database`) или
   заполнена больше чем на 350 МБ из 500 (`storage`, [бюджет хранения](../architecture/data-model.md#бюджет-хранения)).
   Напиши Никите.

**7. Спайк S2b** (§10, этап 1). Критерии: приложение запускается на втором iPhone с другим Apple ID, работают вход через Google
и расширение. Значит, раздать игру одногруппникам реально.
1. Проверь версию iOS: нужна **26.0 или новее**. Ниже — сразу пиши Никите.
2. Дождись, пока Никита пройдёт S2 (#1): если у него не встанет, у тебя тоже.
3. Пройди [install-on-iphone.md](install-on-iphone.md) целиком. Apple ID — твой, но лучше отдельный «расходный», не основной (почему — там же).
4. Пришли Никите три снимка: «Проверка установки», Live Activity на экране блокировки, виджет. Таблицу из шага 4 инструкции
   заполни комментарием к задаче — без Apple ID и личных данных.
5. Вход через Google проверим вторым заходом, когда в приложении появится экран входа, а у Никиты — Google OAuth.

Не вышло с твоим Apple ID — запасной путь из плана: подпись Apple ID Никиты.

**8. Разобраться в сервере.** К защите тебе нужно объяснять конвейер захвата и геометрический контракт (§8). Порядок чтения:
1. [Program.cs](../../backend/src/Gorodki.Api/Program.cs) → `Features/Health/HealthEndpoints.cs` → `Gorodki.Domain/Time/GameClock.cs` и тесты к ним.
2. [runs.md](../architecture/runs.md) и `Features/Runs` — как точки попадают на сервер.
3. [captures.md](../architecture/captures.md) и `Features/Captures/CaptureProcessor.cs` — как заявка петли становится землёй.
4. [ADR 0003](../adr/0003-territory-engine.md), `Gorodki.Domain/Geo/GeoOps.cs`, `Gorodki.Domain/Territory/` — геометрия.
5. Поставь точку останова в тесте из `Gorodki.Domain.Tests/Territory` и пройди его отладчиком (Docker не нужен).
6. Итог — комментарием к задаче: 5–10 строк «своими словами» и список вопросов. Разберём с Никитой и Claude: в плане на обучение
   30 минут в неделю.

## 5. Как работать с репозиторием

- **Один раз:** `git config --global user.name "Trinoto"` и `user.email`. Репозиторий публичный, email из коммитов видят все.
  Можно включить в GitHub **Settings → Emails → Keep my email addresses private** и взять показанный там адрес `…@users.noreply.github.com`.
  Первый `git push` откроет окно входа в GitHub (Git Credential Manager ставится вместе с Git для Windows).
- **Цикл:** задача → ветка латиницей `тип/коротко` (`feat/…`, `fix/…`, `test/…`, `docs/…`, `chore/…`) → коммиты вида
  `feat(backend): описание по-русски` → `git push` → PR по шаблону → зелёный CI → Claude комментирует, Никита сливает (squash) →
  `git switch main` и `git pull`. Одна задача — один PR.
- **`main` защищена:** напрямую не запушить, только через PR с тремя зелёными проверками:
  - `backend` — сборка в Release (любое предупреждение = ошибка), все тесты, включая интеграционные, и Docker-образ для Render;
  - `ios-core` — Swift-пакеты на Linux и оформление Swift-кода;
  - `ios-build` — сборка приложения на Mac. Если `ios/` не менялась, проверка пропускается и считается пройденной.
- **Проверить у себя, как в CI** (предупреждения станут ошибками), из папки `backend`:
  `$env:CI = "true"; dotnet build Gorodki.slnx -c Release; Remove-Item Env:CI`
- **Оформление кода:** `dotnet format Gorodki.slnx --verify-no-changes` (тоже из `backend`) должна пройти молча. CI её
  пока не запускает, но Claude держит код чистым; без `--verify-no-changes` команда сама всё поправит.
- **Правила кода:** имена по-английски, комментарии по-русски. Время — только через `TimeProvider`/`GameClock`. Числа правил — в
  игровом конфиге, не в коде. Версии NuGet — только в `backend/Directory.Packages.props`. `contracts/*.json` руками не правь:
  как их менять, описано в [contracts/README.md](../../contracts/README.md).
- **Нельзя:** секреты в коде, задачах и PR (если секрет попал в коммит — сразу скажи Никите: ключ перевыпускаем, удаления из
  истории мало); треки и данные игроков; координаты тайников; сливать свои PR самому. Не трогай другие репозитории и
  проекты Никиты и чужие проекты Supabase.
