# Развернуть сервер на Render

Для Никиты: аккаунт Render — на нём (PLAN.md, §1: на бесплатном тарифе нельзя добавить участников). Всё остальное уже
готово: база на Supabase создана и мигрирована (issue #35), описание сервиса лежит в [render.yaml](../../render.yaml).
Займёт минут 20, из них 10 — первая сборка.

## Что понадобится

- Аккаунт Render (вход через GitHub `Nikich196` — так проще подключить репозиторий).
- **Строка подключения к базе** — в твоём личном файле доступов «Городков» (Claude записал её туда, когда создавал базу).
  Если файла под рукой нет — Supabase → проект `gorodki` → **Connect** → **Session pooler** (порт 5432), в формате .NET:
  `Host=aws-0-eu-central-1.pooler.supabase.com;Port=5432;Database=postgres;Username=postgres.<ref проекта>;Password=<пароль>;SSL Mode=Require`
- Строку никуда не вставляй, кроме Render: ни в задачи, ни в чат, ни в код — репозиторий публичный.

## Шаги

1. Render → **New** → **Blueprint** → разреши доступ к репозиторию `Nikich196/gorodki` (только к нему).
2. Render прочитает `render.yaml` и покажет сервис `gorodki-api` (Docker, Free, Франкфурт). Он спросит одно значение —
   `ConnectionStrings__Gorodki`: вставь строку подключения. Ключ подписи токенов (`Auth__SigningKey`) Render сгенерирует сам.
3. **Apply**. Первая сборка — около 10 минут. При запуске сервер сам проверит миграции базы (`Database__MigrateOnStartup`);
   они уже применены, так что он просто стартует.
4. Проверь в браузере (адрес — вверху страницы сервиса, примерно `https://gorodki-api.onrender.com`; если имя занято,
   Render добавит суффикс):
   - `/health` — `"status": "ok"`, версия и игровой день;
   - `/health/ready` — `"status": "healthy"`, у проверки `storage` — размер базы (пустая база с PostGIS — около 19 МБ).
5. Адрес сервера отдай Егору для пингера ([#39](https://github.com/Nikich196/gorodki/issues/39)): `GET <адрес>/health/ready`
   **каждые 10 минут** — Render Free засыпает после 15 минут без запросов, Supabase Free встаёт на паузу через неделю простоя.
   И напиши адрес Claude — он пропишет его в сборку приложения.
6. Проверь с телефона **без VPN** (мобильный интернет и Wi-Fi университета), открывается ли `/health` — доступность из РБ
   (PLAN.md, §9). Если нет — напиши Claude: это спайк S9, план Б — в §9.

## Потом

- **Вход через Google** — когда будет OAuth client ID в Google Cloud (твой аккаунт): Render → сервис → **Environment** →
  `Auth__GoogleClientIds__0` = ID сборки Free, `Auth__GoogleClientIds__1` = ID сборки Paid (если есть). Без них вход через
  Google отвечает 503 — так и задумано.
- **Автодеплой**: новая версия уходит на Render сама, когда в `main` приходит изменение сервера (`backend/`) **и все
  проверки GitHub зелёные** (`autoDeployTrigger: checksPass`). План (§8) говорил о deploy hook; встроенная настройка Render
  делает то же самое без секрета в GitHub.
- **За неделю до показа** (Д−7, заморозка, §8): Render → сервис → **Settings** → Auto-Deploy → **Off** (и в `render.yaml`
  поставить `off`, чтобы синхронизация Blueprint не включила его обратно).
- Лимит Render Free — 750 часов в месяц на всё рабочее пространство, а один сервис без сна тратит ~720: второй сервис
  заводить нельзя, иначе часы кончатся и сервисы остановятся до конца месяца (PLAN.md, §2).

## Если что-то пошло не так

| Что видишь | В чём дело |
|---|---|
| Сборка упала на `dotnet publish` | Проверь, что CI на `main` зелёный; пришли Claude лог сборки |
| Сервер падает при старте: «Auth:SigningKey должен быть Base64-строкой не короче 32 байт» | Переменная `Auth__SigningKey` пустая или короткая — задай случайные 32 байта в Base64 (например, `openssl rand -base64 32`) |
| `/health/ready` отвечает 503, у `database` — `unhealthy` | Неверная строка подключения или база на паузе (Supabase → Restore) |
| `/health/ready` отвечает 503, у `storage` — `degraded` | База больше 350 МБ из 500 — пора чистить ([бюджет хранения](../architecture/data-model.md#бюджет-хранения)) |
