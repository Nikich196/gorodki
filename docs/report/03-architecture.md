# 3. Архитектура

Глава описывает систему такой, какая она есть в репозитории на 24.09.2026; то, что ещё только запланировано, помечено.
Подробные решения с альтернативами — в `docs/adr/` (ADR — «архитектурное решение»: что решили, почему, что отвергли).

## 3.1. Общая схема

```
iPhone (Swift 6, SwiftUI)                        Сервер (ASP.NET Core 10, Render Free, 1 экземпляр)
┌───────────────────────────┐   REST + JSON     ┌───────────────────────────────────────────────┐
│ приложение                │ ────────────────► │ API по функциям: вход, забеги, захваты, карта, │
│  ├ GameCore (правила лиг, │   OpenAPI-клиент   │   туман, рейтинги, профиль, админ              │
│  │  петля, туман)          │                    │ Gorodki.Domain: движок участков (NTS),        │
│  ├ Sync (очередь забегов)  │ ◄──── SignalR ──── │   правила, туман, судья отрезков               │
│  ├ Networking (токены)     │   подсказки        │ фоновый обработчик: захваты, визиты, туман,   │
│  └ Persistence (GRDB)      │                    │   откаты, чистки, срез рейтингов              │
└───────────────────────────┘                    └──────────────────────┬────────────────────────┘
                                                                        │ EF Core + Npgsql
                                                  ┌─────────────────────▼─────────────────────────┐
                                                  │ Supabase Free: PostgreSQL 17 + PostGIS 3.3.7   │
                                                  │ схема app, 16 таблиц, 500 МБ                    │
                                                  └────────────────────────────────────────────────┘
```

Телефон записывает забег и отправляет его кусками; сервер судит след, применяет захваты к общей карте и раздаёт карту
по тайлам 1 × 1 км. Реальное время — подсказки «перезапроси», сами данные — только через REST (раздел 3.5).

## 3.2. Ключевые решения

| Решение | Почему | Что отвергли |
|---|---|---|
| **Нативное iOS-приложение** (Swift 6, SwiftUI) | Фоновая геолокация, Live Activity, PiP, камера, NFC — пункты листика (§4 плана) требуют системных API iOS; показ — на iPhone | Кроссплатформенные фреймворки: хуже доступ к фоновым режимам iOS |
| **Точные участки по контуру следа** (ADR 0003) | «Сколько пробежал — столько получил» — главная идея игры; спайк S13: на финальном движке 28 000 случайных историй без нарушений (там же честно записана одна необъяснённая аномалия первого прогона) | Гексагональная сетка H3 и растр 1–2 м — проще, но контур «ступенькой» |
| **Один движок геометрии для записи** — NetTopologySuite в памяти сервера, PostGIS только хранит | Однопоточный движок с блокировками тайлов проще проверять: инварианты, растровый оракул, одновременные захваты = последовательный повтор | Геометрия в SQL: труднее тестировать и отлаживать |
| **Хостинг за $0**: Render Free + Supabase Free | Бюджет проекта — $0 (§1 плана) | Платные облака |
| **Клиент API генерируется из OpenAPI** (ADR 0004) | Контракт один — сервер и телефон не расходятся; «пыточный» набор проверен спайком S6 | Ручной клиент |
| **Свой фоновый обработчик** (ADR 0005, предложено) | Захват обрабатывается за секунды после заявки, строго по одному — это очередь, а не расписание | Hangfire для очереди; для задач по расписанию — решает Никита (issue #54) |

## 3.3. Сервер

**Два проекта.** `Gorodki.Domain` — чистая логика без базы и сети: движок участков `TerritoryMap` (узлование,
разбиение на грани, правила куска, журнал и откат), правила уровней, туман, судья отрезков, календарь сезонов, игровой
конфиг. Он тестируется обычными и property-тестами (CsCheck). `Gorodki.Api` — адреса, база, фоновая работа.

**Адреса по функциям** (Minimal API, папка на функцию): `Auth` (Google → свой JWT, обновление токенов с «льготным
окном»), `Runs` (забеги и куски), `Captures` (заявки петель, обработчик, журнал, откат, визиты), `Territory` (карта
с публичной задержкой), `Fog` (туман), `Leaderboards`, `Seasons`, `Me` (профиль, приватные зоны, «мои данные»,
удаление), `Admin`, `Realtime`, `Health`. Всё закрыто по умолчанию: открытые адреса помечены явно.

**Захват — два шага.** Шаг A без блокировок: судья отрезков, кольцо петли, контур. Шаг B — короткая транзакция под
блокировками игрока, устройства и тайлов (по порядку): суточный лимит, движок, разница кусков, журнал для отката,
рост версий тайлов. Поэтому одновременные захваты соседних игроков корректны, а медленный захват не держит всю карту.

**Фоновый обработчик** (`CaptureWorker`, один поток): каждые 5 секунд или по сигналу — захваты, визиты, туман,
раскрытия для реального времени, откаты; раз в час — чистки (журнал 7 дней, сырые точки 14 дней), закрытие забытых
забегов, удаление аккаунтов, срез рейтингов. Идемпотентность — аренда заявок и отметки у забегов: повтор и второй
экземпляр сервера во время деплоя ничего не удваивают.

**Приватность — сквозное правило.** Всё, что сообщает о чужих изменениях (карта, реальное время, рейтинги, выгрузка
данных), идёт через одну границу публичности: «сейчас − 20 минут», пачками по 5 минут (`TerritoryReader.PublicHorizon`).
Карта отдаёт «видимую версию» тайла, в которой скрытый захват не виден даже как изменение числа (глава 7).

**Данные.** 16 таблиц в схеме `app` (`docs/architecture/data-model.md`): пользователи и токены, забеги и куски точек,
захваты и журнал, куски земли (`geometry`), версии тайлов, туман по тайлам (сжатые биты), сезоны, откаты, приватные
зоны, срезы рейтингов, конфиг. Миграции — EF Core; каждая правка модели без миграции роняет тест.

## 3.4. Телефон

Логика вынесена из приложения в Swift-пакеты без UIKit и SwiftUI — их тесты идут на Linux в CI и на Windows (WSL) без Mac:

| Пакет | Что внутри | Тестов |
|---|---|---|
| `GameCore` | Правила лиг, судья отрезков, детектор петли, сетка и слои тумана, геодезия | 52 |
| `GorodkiAPI` | Клиент, сгенерированный из `contracts/openapi.v1.json` | 11 |
| `GorodkiSync` | Очередь забега (`RunRecorder`), доставка по контракту (`SyncEngine`), расписание повторов (`SyncScheduler`) | 55 |
| `GorodkiNetwork` | Клиент на URLSession, токены в Keychain, обновление при 401 (одно на все запросы) | 34 |
| `GorodkiPersistence` | База приложения на GRDB (WAL), очередь синхронизации в ней | 10 |
| `GorodkiKit` | Дизайн-система и платформенные обёртки | — |

**Главное правило телефона — никогда не ждать сервер.** Забег пишется в очередь на телефоне и уходит, когда есть сеть;
любой запрос безопасно повторить (идентификаторы создаёт телефон, повтор куска сервер узнаёт по отпечатку). Очередь
в GRDB переживает выгрузку приложения.

**Ещё не сделано** (этап 2): трекинг (`TrackingEngine`, CoreLocation), карта и туман на MapKit, экраны, вход через
Google (ждёт Client ID), клиент реального времени, фоновая выгрузка (BGTasks).

## 3.5. Контракты и синхронизация

- **OpenAPI** (`contracts/openapi.v1.json`) генерируется сервером и проверяется тестом; копия для Swift — тоже;
  образцы ответов (`contracts/samples`) разбирают тесты обеих сторон.
- **Игровой конфиг** (`contracts/game-config.v1.json`): все числа правил. Телефон и сервер судят забег одной версией
  конфига — той, с которой забег начат.
- **Реальное время** (`docs/architecture/realtime.md`): SignalR-хаб раздаёт только подсказки — «заявка решена» автору
  и «тайлы изменились» (чужие — не раньше границы публичности); данные — через REST. Потеря подсказки ничего не ломает:
  приложение пересинхронизируется при подключении.

## 3.6. Сборка, проверка, развёртывание

- **Ветка → pull request → зелёные проверки → слияние.** Основная ветка защищена обязательными проверками: сервер
  (сборка Release без предупреждений, все тесты, включая ≈90 интеграционных на образе той же PostgreSQL + PostGIS,
  что в Supabase, и Docker-образ), Swift-пакеты на Linux и оформление кода, сборка приложения на macOS (Debug,
  Release-Free, Release-Paid).
- **Развёртывание**: `render.yaml` — сервис из `backend/Dockerfile`, автодеплой только после зелёных проверок;
  миграции базы применяются при старте. Готовность — `/health/ready` (база и бюджет хранения, 503 с 350 МБ).
- **Проверка качества сверх тестов**: мутационные проверки (намеренная поломка кода должна ронять тесты) и критика
  дизайна отдельным агентом до кода — она, например, нашла утечку местоположения через версии тайлов (исправлено).
